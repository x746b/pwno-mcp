Use the `pwncli` family when you want an interactive exploit driver that stays attached to a specific debug session.

<Warning>
  `pwncli` requires an existing session. Call `create_debug_session` first and use
  the same explicit `session_id` for every driver I/O call.
</Warning>

## `pwncli`

`pwncli` writes the provided script into the session runtime directory, launches it with the same locked Python environment as the MCP server, and exposes both startup output and any parsed attach result marker.

```json
{"tool":"pwncli","arguments":{"session_id":"chal-a","binary_path":"/workspace/chal","file":"from pwn import *\nprint('ready')\n"}}
```

### Important returned fields

- `runtime_dir`: session-specific directory used for the inline script
- `io.current_output`: output collected for this call
- `io.current_output_b64`: the same output as exact base64-encoded bytes
- `attachment.result`: parsed attach result marker when present
- `startup.ready`: whether the driver reached a ready state
- `startup.reason`: why the wait finished
- `startup.alive`: whether the driver is still alive
- `startup.pid`: driver process id
- `startup.replaced`: whether an older driver was replaced for this session

`startup.ready` means the initial wait observed attach, output, or exit activity. It
does not mean the exploit completed. If `startup.alive` is true, continue the I/O
loop and use `checkevents` to determine completion.

## I/O tools

```json
{"tool":"sendinput","arguments":{"session_id":"chal-a","data":"AAAA\n"}}
{"tool":"sendinput","arguments":{"session_id":"chal-a","data":"","data_b64":"/wBB"}}
{"tool":"checkoutput","arguments":{"session_id":"chal-a"}}
{"tool":"checkevents","arguments":{"session_id":"chal-a"}}
```

- `sendinput` writes UTF-8 text with `data`, or exact bytes with `data_b64`
- `checkoutput` returns buffered display text plus `output_b64`, then clears it
- `checkevents` drains structured events and returns `alive`, `exit_code`, and `driver_pid`

Output events use `type: "out"` or `type: "err"` and contain both display-safe
`data` and exact `data_b64`. Exit events use `type: "exit"` with an integer `code`.
Empty output is not proof of process completion; poll until `exit_code` is non-null
or `alive` is false.

<Warning>
  `sendinput` does not append a newline automatically.
</Warning>

<Tip>
  Use `data_b64` for exploit payloads containing NUL bytes, non-UTF-8 bytes, or
  other values that must survive transport unchanged.
</Tip>

## Session management tools

```json
{"tool":"pwncli_stop","arguments":{"session_id":"chal-a"}}
{"tool":"list_pwncli_sessions","arguments":{}}
```

- `pwncli_stop` kills the driver bound to a session
- `list_pwncli_sessions` lists all active drivers

## Behavior notes

- one `pwncli` driver per debug session
- launching a new driver for the same session replaces the old one
- `close_debug_session` also stops the session's active driver
